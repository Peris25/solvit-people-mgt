## Session and MFA review

- New access-token lifetime defaults to **15 minutes** and cannot be increased beyond 15 by the existing environment setting. Secure HttpOnly authentication cookies remain in place; there is no new token storage dependency.
- New tokens carry an original session-start timestamp. Refresh preserves it, enforcing absolute **8-hour HR, 12-hour other staff, 24-hour Solver** limits. The current refresh expiry remains 12 hours by default; this is intentionally not extended to the FRD's seven days without approving the combined session policy. Existing ordinary login/password flows remain compatible.
- Refresh rotation is serialized using the existing persistent MongoDB integrity lock. Concurrent reuse cannot mint two successful token pairs; real MongoDB tests verify this. New token families retain a stable session identifier so logout invalidates copied access tokens across rotation. Password-change timestamps, account activity, global invalidation and required-first-login checks still apply on direct requests and refresh.
- `/auth/me` now returns explicit identity fields, never arbitrary account fields, hashes, OTP/MFA secrets or recovery codes. Additional known secret fields are removed from authenticated account objects as defense in depth.
- Browser mutations, including login/logout/refresh, reject untrusted Origin values and cross-site/same-site browser requests missing Origin. The allowlist uses explicit configured frontend/CORS origins and the request origin; credentialed CORS no longer falls back to `*`. Non-browser clients without browser Origin/fetch headers retain API compatibility.
- **MFA is not implemented.** No existing enrolled TOTP challenge, encrypted secret lifecycle, enrolment/recovery interface or approved operational recovery process was found. No unverified provider or unavailable credentials were introduced. Brief-required privileged MFA remains a **launch blocker**, requiring a dedicated tested increment and HR/IT approval of enrolment/recovery. Removing secrets from responses is not MFA enforcement.
- Existing lockout/rate-limit caches are per process. Shared enforcement across multiple workers/proxies remains an operational/security dependency; do not claim a distributed account lockout. Reverse-proxy host validation, HTTPS, trusted forwarding and modern browser-origin behavior must be verified in staging.
- Old tokens issued before this change retain their signed expiry, and old rotation chains cannot be retroactively assigned a complete family history. They still pass live password/account/invalidation/first-login checks. A separately authorized session cutover/invalidation plan is required before deployment; this task did not invalidate production sessions or change signing secrets.

## Remaining decisions and staging/launch gates

1. **Privileged MFA and shared lockout** remain as described above. Do not declare full authentication-policy or launch closure. Approve combined-role, session lifetime, recovery and old-session cutover requirements; no existing account is silently enrolled, reset or locked out by development.
2. **HR privacy/workflow decisions:** approve disciplinary progress-only manager/subject views, exact policy audiences and publication/version rules, role/department aliases, independent reviewers, payroll document release and financial approval rules. Existing confidential rows default conservatively; no historical sharing migration occurred.
3. **Functional gaps remain in Task 17:** complete project reward approval, recruitment assessment/panel proof, authoritative financial worksheets/rates, survey content/cascade definitions and historical attrition basis require approved source inputs. Security checks do not approve legacy financial formulas or prove full FRD acceptance. Missing announcements, events/requests expansion, OTP and external integrations remain separate development work.
4. **Data/index prerequisites:** reconcile actual employee/account/Solver links, duplicate normalized identifiers, stale managers, policy audiences/versions and historical workflow states on an approved local/staging snapshot. New deterministic response/ack keys use MongoDB's existing `_id` uniqueness, but historical aliases and other uniqueness protections still depend on application serialization until approved normalized indexes exist. Direct DB writers and older API workers can bypass application checks. No production index/backfill was run.
5. **Interrupted writes:** operations reuse the existing global persistent lock, with no automatic expiry/removal. Required audits precede writes; they record intent and do not prove downstream completion. A crash may leave partial records, notification or file work and a retained lock. Quiesce all writers and follow `docs/integrity-lock-recovery.md` / `docs/employee-integrity-rollout.md`; inspect before deciding recovery. No transaction/outbox or automatic reconciliation is claimed.
6. **Private storage/scanner:** configure durable private employee, leave-evidence and separate policy roots, trusted malware scanner/signature updates, encryption/ACLs, ingress limits, retention, backups and tested restoration. New policy uploads now fail closed if scanning is unavailable; historical files are not automatically rescanned, shared or deleted. Confirm operational acceptance of legacy DOC/PPTX downloads while new uploads follow the approved five-type list.
7. **Staging operations:** identify the actual host/operator; validate explicit CORS/frontend origins, HTTPS/cookies, proxy Host/forwarding policy, all workers on one reviewed build, scheduler concurrency, fail-closed audit/storage outages and email routing. Use isolated DB/files and outbound delivery sinks; no provider messages should escape to live recipients. A configured role must not be granted extra fields just to make a UAT screen pass.
8. **HR UAT:** test every role, revoked grants, linked/unlinked/exited accounts, canonical/storage aliases and duplicates, manager reassignment, independent Finance/HR reviewers, private downloads, mobile recognition, refresh races and operator recovery. Complete broader sensitive-access/audit, accessibility, capacity, retention and operational review before production sign-off. This task's targeted security regression suite is not a penetration-test certification.
