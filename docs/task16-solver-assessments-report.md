## Completed workflows

- **Settings and assignment:** Draft → Published configuration; every edit creates a new version. Publishing requires complete approved settings. A pending assignment in the same bank cannot be duplicated, including concurrent requests. A passed version cannot be repeatedly reassigned; a failed attempt's approved re-sit interval is preserved across later versions.
- **Solver experience:** Assigned → InProgress → AwaitingScoring. Candidates see only their assigned attempt, cannot open Part B before submitting A, can save/clear answers, and cannot change submitted work. Stale revisions are rejected. Explicit progress saving is available; automatic background autosave is not claimed.
- **Scoring and release:** Assigned assessor supplies marks only for manual questions within approved maximums; automatic marks cannot be supplied by the client. Unanswered manual questions cannot receive positive marks. Scored results remain private until release; configured borderline results require independent Technical Manager review first. Existing scores cannot be edited through these routes after scoring/release.
- **Competency history:** Explicit HR evidence verification appends records rather than overwriting old entries or Solver assignments. Read-time status labels expired evidence without rewriting records. Legacy vehicle categories remain separately labelled as unverified by this workflow. Competencies/qualifications are visible in the existing Solver profile even when no new assessment has been assigned.
- **Documents:** Reuses Task 15 ownership, size/type/content checks, malware scan, private storage root, download containment and audit. New `hr_assessment` sharing is an explicit HR choice for non-confidential assessment evidence. It does not replace HR-only defaults. Only the subject and explicitly assigned assessors/HR can download a document through an attempt, and only if it is an actual answer in that attempt and still shared/clean/available. Personal documents and arbitrary document IDs cannot be fetched through this adapter.
- **Integration:** Existing Solver profile/dashboard/navigation link to the assessment page. Staff Home surfaces authorized pending scoring/review actions. Notification Centre uses recipient-scoped, deterministic events and authorization-checked links with generic previews. Existing reporting supports HR assessment status/released-result reporting and executive aggregates; exports never include keys, answers, notes or storage paths. No new SMS/email/OTP/external-app delivery was added.

## Security and interrupted-write recovery

All mutations reuse the existing persistent MongoDB integrity-write lock. Attempts also require the current integer revision and compare-and-set that revision during updates. Settings, assignments, submissions, outcomes and competency records remain `Pending_Audit` until required audit/notification writes succeed. Pending operations cannot be scored/released/retried as completed, and pending results do not become visible to the subject.

No automatic lock expiry, speculative rollback or blind publication is implemented. Follow the existing Task 02/15 controlled operator procedure: stop all writers; establish that an old worker/write is no longer active; inspect the affected version/attempt/revision and partial audit/inbox records; reconcile missing steps; publish Ready only after verified completion; remove a stale lock only once safe. New versions do not modify or repair a pending predecessor. No such recovery was run against production.
