# Production QA review — 19 October 2026

## Assessment

**Production is reachable and the main HR screens render, but this is not a full QA pass or an all-role security sign-off.** Confirmed data, configuration and interface defects remain. Resolve the high-priority findings before relying on reporting relationships, statutory calculations or policy acknowledgements for operational decisions.

This review examined the live `https://people.solvit.co.ke` application using its existing signed-in HR Admin session, and the public API at `https://solvit-people-management.onrender.com`. Automated regression tests ran separately against local code, never against production data. The reviewed repository revision is `97f996773321e6e3961bd8030ef5118236480ef4`. The deployed frontend was previously verified byte-for-byte against that build. The backend health response does not expose a commit identifier; the exact deployed backend revision remains unverified independently of Render's deployment display.

## Method and limits

- Reviewed 36 distinct production screens/dashboard views, including their available data and empty states. Navigation, search, department filtering, modal opening/closing and a mobile viewport were exercised.
- Inspected related code to distinguish confirmed interface defects from policy/configuration gaps. Revisited initial loading states; transient spinners were not classified as defects.
- No employee, candidate, leave request, assessment, document, salary, bank detail, workflow decision, permission or MFA setting was created, edited, approved or deleted. No email, notification delivery, AI prompt, import, export or acknowledgement was submitted. Existing endpoints may record their normal access/audit events.
- A leave application modal was inspected and date fields were entered without submission, then cancelled. End-to-end leave preview/submission was not certified.
- Phone-size testing used a temporary 390 × 844 viewport. The viewport and expanded sidebar were restored afterward.
- Ordinary employee, manager, Finance, IT, executive and Solver production sessions were not available for separate authenticated role testing. HR visibility alone does not establish employee privacy or manager scope. No production impersonation or credential bypass was used.
- Automated integration tests that require fixture reset/deletion were deliberately not pointed at production. Their skips are explicitly counted below.
- Confidential employee/candidate values, salaries, private contact details, credentials and private document paths are omitted from this report. Aggregate counts describe only the observed screens at review time.
- Browser-control detachment interrupted some later interactions; a fresh tab allowed the main review to continue. This is a tooling limitation, not evidence of an application defect.

## Follow-up tests required for a full QA sign-off

1. Use designated, least-privileged test employee, manager, HR, Finance, IT and Solver accounts. Verify role navigation and API denial with copied/forged identifiers, tenant boundaries and changed-manager/account states. Do not use real employee decisions as test fixtures.
2. Run the 321 skipped integration tests against a separate controlled test target with the expected reset fixtures. Production must never receive their reset/delete requests. Retest database concurrency/index/lock recovery separately.
3. Exercise an explicitly approved synthetic production leave case: submit, manager recommendation, HR decision, rejection, withdrawal, overlap, working days/holidays, handover, balance preservation and private evidence. Check notification recipients and audit events.
4. Configure and verify privileged MFA enrollment, replay/rate limits, recovery and password/role/deactivation session invalidation with a rollback/support plan.
5. Validate scanner clean/malware/outage cases, 20 MB employee files and 5 MiB leave files, private paths, authorized downloads, actual proxy/body limits and durable storage/restore. Code's default global body limit is 6 MiB (`backend/utils/security.py:34`); actual production configuration was not inspected, so a production 20 MB failure is a risk, not a demonstrated defect.
6. Verify HR-approved reference roster and reporting changes with an audited dry-run. Do not conflate intake candidates, active Solvers and directory members. Preserve exited/board/historical records.
7. Check complete onboarding/offboarding and approved timing of deactivation; complete training and performance cycles including independent approvers, historical visibility, scoring policy and notifications.
8. Test export field redaction and spreadsheet formula injection for each authorized role, and anonymous/other-user downloads. This review intentionally downloaded no private employee exports.
9. Complete mobile/tablet layouts, keyboard navigation, focus trapping, contrast, 200% zoom, desktop Chrome/Edge and supported Safari/Firefox. Dark mode, assistive technology and browser matrix are not certified here.
10. Conduct deliberate timeout/offline/server-error testing on a controlled target, plus load/concurrency, scheduled-job ownership, backup restoration and operational monitoring. No production fault injection or load test was run.

## Recommended order

1. **Immediate operational controls:** configure privileged MFA safely; communicate that statutory outputs and unreadable-policy acknowledgements must not be relied on; confirm deployment/scanner/storage readiness. These require IT/Finance/HR input, not fabricated defaults.
2. **Small code corrections:** mobile navigation, recruitment stage/count completeness, calendar range/deadline presentation, calculator policy separation, readable-policy publication/acknowledgement gating and upload error feedback. Add focused regressions for each before deployment.
3. **HR data reconciliation:** approve individual reporting-cycle corrections, department/identity mapping, reference FTE/Solver reconciliation and onboarding due dates. Apply separately with audit history and reviewed backups.
4. **UAT sign-off:** designated role accounts, full write-workflow matrix, scanner/storage/restore and all skipped integration tests. Record pass/fail evidence rather than treating a rendered screen as a completed workflow.
